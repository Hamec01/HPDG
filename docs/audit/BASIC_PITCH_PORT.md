# Basic Pitch in C++ — HPDG's own audio-to-notes transcriber

Stage 6 (Sample Analysis), follow-up of `TASK_TRANSCRIPTION_KEY.md`. Spotify's Basic Pitch
(ICASSP 2022 model, Apache-2.0, `docs/third-party/basic-pitch`) ported to plain C++ with no
runtime dependency: `Source/Analysis/BasicPitch/`. Wired into the sample key in phase 4 (below),
on the maintainer's decision of 2026-11-02.

## What was ported

- `BasicPitchTranscriber::infer`: the same 2 s windows with a 30-frame overlap as
  `basic_pitch.inference`, the nnAudio CQT2010v2 (309 bins, 9 octaves, 256-tap kernels and
  half-band filter), NormalizedLog, harmonic stacking (0.5, 1 .. 7), and the seven convolutions with
  batch norm, ReLU and sigmoid. 16 864 trained parameters plus the CQT kernels in
  `BasicPitchWeights.cpp`, generated by `tools/basic_pitch_export.py weights`.
- `BasicPitchTranscriber::notes`: `output_to_notes_polyphonic` with `predict()`'s defaults
  (onset 0.5, frame 0.3, 127.7 ms, inferred onsets, melodia trick).
- `estimateKeyFromNotes`: arm B2 of `tools/transcription_key.py` (the plugin's Albrecht-Shanahan
  profiles, minor prior 0.1, bass 0.2, opening note 0.5).
- `resampleTo22050`: a tabulated windowed sinc (Python uses soxr through librosa).
- SSE2 inner loops (any x64), windows on several threads.

On the same note files, `estimateKeyFromNotes` gives the same key as the Python B2 in 373 of 373 loops.
The other 7 loops have no notes.

## Key on the 380 loops (MIREX weighted, `transcription_key.py report`)

| arm | MIREX | exact |
|---|---|---|
| C, the plugin today (`key3`) | 0.652 | 56.3 % |
| B2, Python Basic Pitch notes | 0.690 | 62.6 % |
| B2, C++ port | 0.690 | 62.6 % |
| B2, or C when no notes were found | **0.698** | **63.4 %** |

Per pack, "B2 or C" against C: +0.034 techno music, +0.073 techno bass, +0.007 Cymatics Diamonds,
+0.003 Cobra, +0.058 Lofi, +0.025 RHH melodic, +0.012 RHH bass, +0.079 DnB music, +0.089 DnB bass.
That is 9 of 9 packs better and none worse. Nothing is tuned on this set: the weights are the
plugin's own.

Against the task's gate (≥ 0.05 MIREX, ≥ 6 / 9 packs better, no pack worse by > 0.03): the packs
pass, but the overall gain is +0.046, just under 0.05. The confidence criterion has not been
measured yet.

A margin threshold (B2 only when best − second > 0.1) would give 0.708, but that threshold is
chosen on this test set, so it is not taken.

## Speed (380 loops, 3833 s of audio, this PC)

| | x real time | per 10 s of audio |
|---|---|---|
| Python Basic Pitch, ONNX Runtime (`run1`), with decoding and resampling | 40.8 (52 without the first file's warm-up) | p50 0.19 s |
| C++ port, 1 thread, resampling counted, decoding not | 24.3 | p50 0.41 s, p95 0.53 s |
| C++ port, 8 threads | 66.8 | |

The C++ port has no warm-up, while Python's first file took 20 s. The cost is in the first contour
convolution (3 × 39 over 8 harmonics, 340 M multiply-adds per window), which runs close to the SSE
peak. An AVX2 / FMA path picked at run time would give about 2× more if needed.

## Phase 4 — the key from notes in the plugin

The maintainer chose to go ahead below the 0.05 gate (+0.046, 9 / 9 packs). One change in
`SampleHarmonyAnalyzer::analyze`: after the chroma key, Basic Pitch transcribes the sample (up to 4
threads, on the analysis thread, never in the audio callback); when it finds notes, their key
(`estimateKeyFromNotes`, arm B2) replaces the chroma one, with the same confidence formula
(`(score - 0.35) / 0.45 x margin / 0.08`) and the same fifth check (cap 0.45) on the note
histogram. No notes: the chroma key and confidence, unchanged. The file-name label and the user's
manual key still win after it. No weight is fitted: it is "notes, else chroma", as measured.
`SampleHarmony::notes` keeps every transcribed note for later use (pattern generation).

Before / after, `HPDG_BreakLab analyze --harmony`, the same 380 files, no labels:

|---|---|---|
| MIREX | 0.652 | **0.698** |
| exact | 56.3 % | **63.4 %** |

`kMinKeyConfidence` (0.4): 46 loops cross it upwards and 29 downwards; 327 -> 344 loops have their

Per pack (MIREX): techno music 0.782 -> 0.816, techno bass 0.750 -> 0.823, Cymatics Diamonds
