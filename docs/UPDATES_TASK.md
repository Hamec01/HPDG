# Задание: обновления HPDG через сайт (только для покупателей)

Дата: 2026-10-19. Владелец решения: HamloProd (мейнтейнер). Решение принято: установщик
получают **только покупатели**, через hamloprod.org. Публичный GitHub для установщика
не используется, токены в плагин не зашиваются.

## Что уже есть (main, коммиты c6f8535, f1d31b0)

- Версия задаётся в одном месте: `CMakeLists.txt` → `project(HPDG VERSION x.y.z)` +
  `set(HPDG_VERSION_LABEL "beta.N")`. Шапка плагина, установщик (`Installer/Build-Beta.ps1`,
  `Installer/HpdgVersion.ps1`) и имена файлов берут её оттуда. Сейчас 0.1.0 Beta 3.
- `Source/Services/UpdateCheckService.*`: при открытии плагина один фоновый запрос к
  `https://api.github.com/repos/Hamec01/HPDG_beta-releases/releases` (публичный репозиторий
  **только с релизами: тег + описание, без кода и без установщика**). Если тег новее
  текущей версии, в шапке появляется кнопка `Update: <версия>`; клик открывает
  https://hamloprod.org/en/vst. Ручной кнопки «Проверить обновления» нет.
- Репозиторий `Hamec01/HPDG_beta-releases` ещё **не создан**.
- Тесты: `Tests/CoreStage0Tests.cpp` → «Update check versions and GitHub releases».

## Цель

1. В плагине — небольшая постоянная кнопка **Update** в шапке (рядом с версией под HPDG).
2. По клику плагин проверяет, есть ли версия новее.
3. Если есть и пользователь — покупатель, плагин скачивает установщик, проверяет SHA-256 и
   запускает его (установщик сам просит закрыть DAW: `CloseApplications=yes` в `HPDG_VST3.iss`).
4. Если не покупатель / нет ключа — показывает, что есть новая версия, и открывает страницу покупки.

## Архитектура (рекомендуемая)

**Сайт (hamloprod.org, Next.js на Vercel) — источник правды:**

- `GET /api/hpdg/latest` → `{ "version": "0.1.0-beta.3", "title": "...", "notes": "...",
  "page": "https://hamloprod.org/en/vst" }`. Публично, без файла. Можно читать из
  `HPDG_beta-releases` на сервере или из конфига сайта — тогда GitHub-репозиторий не нужен.
- `POST /api/hpdg/download` с `{ "licenseKey": "..." }` → проверка покупки (Stripe: платёж /
  клиент, ключ выдан после покупки и отправлен письмом через Resend) → ответ
  `{ "url": "<подписанная ссылка на 10 минут>", "sha256": "...", "version": "..." }`.
- Установщик хранится **приватно** (Vercel Blob private / S3 / приватный GitHub-релиз,
  который сервер читает своим токеном — токен живёт только в переменных окружения Vercel).
- Ключ лицензии: выдаётся вебхуком Stripe `checkout.session.completed`, хранится в базе
  (Vercel KV / Postgres), привязан к email. Ограничение: N скачиваний в сутки на ключ.

**Плагин:**

- Кнопка **Update** всегда видна (маленькая, в строке под «HamloProd 0.1.0 Beta 3»).
  Состояния: «Update» → «Checking…» → «Up to date» / «Update: 0.1.0 Beta 4» / «Offline».
- Проверка версии — `GET /api/hpdg/latest` (заменяет запрос к GitHub в `UpdateCheckService`;
  сравнение версий `update::compare` и разбор тегов уже готовы и покрыты тестами).
- Поле для ключа лицензии (один раз; хранить в настройках пользователя
  `%APPDATA%\HamloProd\HPDG`, не в проекте DAW).
- Скачивание в фоне (`juce::Thread`), прогресс на кнопке, проверка SHA-256 из ответа сервера,
  разрешены только ссылки на домены хранилища из белого списка; затем подтверждение
  «Закройте DAW — установщик запустится» и `juce::File::startAsProcess()`.
- Никаких секретов в бинарнике. Ошибки сети — тихо, без зависания UI.

## Что нужно от мейнтейнера до начала

- Где хранить установщик (Vercel Blob / S3 / приватный GitHub-релиз).
- Формат ключа и как его получают текущие покупатели Beta 1–3 (разослать ключи по базе Stripe).
- Нужен ли вообще `HPDG_beta-releases` на GitHub, если версия отдаётся с сайта.

## Критерии готовности

- Покупатель с ключом: Update → скачано → SHA-256 совпал → установщик запущен → после
  установки и перезапуска DAW в шапке новая версия.
- Без ключа: видно, что есть новая версия, ссылка ведёт на страницу покупки; файл получить нельзя.
- Сайт недоступен: плагин работает как обычно, кнопка пишет «Offline».
- Тесты: разбор ответа `/latest` и `/download`, белый список URL, проверка SHA-256, сравнение версий.
- Изменения не трогают генерацию ни одного жанра (docs/RULES.md).
